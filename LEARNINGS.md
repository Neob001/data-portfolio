## 2026-09-15 — revenue sprint (niche scan, price realignment, 5 builds)
- **Critical bug found in staging, fixed portfolio-wide:** `sinceLastRun` cursors were saved to `Actor.openKeyValueStore()` (the run's DEFAULT store), which is brand new on every run -> incremental mode never worked on SEC, TED, Federal Register, FDA (and first SAM.gov build): a scheduled customer would have been re-delivered and re-charged the same records daily. Fix: shared/js/incremental.js — cursor in a NAMED store (`factpipe-<slug>-state`, persists in the runner's account), boundary date re-read and deduplicated by record ID. Rule: every incremental actor must pass a two-pass staging test (pass 2 returns 0 new records).
- Free-text PII: dropping contact columns is not enough — SAM.gov descriptions embed contracting officers' emails and phones. Redact emails/phones in free text (separators required so solicitation numbers, NAICS codes and amounts survive).
- Market reality (niche_demand_scan.py, 54 safe niches): official-data niches are tiny and crowded (top-10 combined users/30d: SEC 26, sanctions 9-12, clinical trials 8) with prolific AI-generated catalogs everywhere (ryanclinton, nexgendata). Best signal combo for new builds: small total result set (<300 -> page 1 by default) + real run volume + high incumbent failure rate (Lighthouse: 158-258 results, 7.5k-11.6k runs/mo, 15-24% failing).
