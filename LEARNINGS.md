# Learnings (append-only)

## 2026-09-11 — bootstrap session
- Apify Store API (`/v2/store`) is public, no token needed, and returns 30-day run stats incl. FAILED counts, review ratings and full PPE pricing of incumbents — the whole opportunity scan is zero-token. `opportunity_scan.py` weights: log10(demand) × weakness × legal ÷ sqrt(build hours).
- Scan results 2026-09-11: uk-company-lookup demand dwarfs everything safe (21,687 incumbent runs/30d, unrated incumbents); TED incumbents fail 13.7% of runs (reliability is the wedge); SEC incumbents avg 4.0 rating with PPE at ~$0.01/filing (price+quality wedge). Google Trends & Product Hunt have big demand but fail our legal-safety filter — do not revisit.
- SEC full-text search endpoint `efts.sec.gov/LATEST/search-index` works keyless but REQUIRES a User-Agent header identifying the caller; returns 100 hits per page (corrected 2026-09-15 — an earlier note said 10, which caused overlapping pages); dates only apply with `dateRange=custom&startdt=&enddt=`.
- TED API v3 `POST /v3/notices/search` works keyless; multilingual fields come as `{lang: [values]}` maps (prefer `eng`); CPV codes arrive duplicated — dedupe; pagination via `page` or `iterationNextToken`.
- Companies House API has NO keyless access; decision: customers supply their own free key via secret input (removes our rate-limit exposure, zero owner ops). Officer/PSC data excluded from v1 as PII — owner legal call requested.
- Node 22.16 `node --test <dir>` fails; must glob `tests/*.test.mjs`.
- Local machine has no gh CLI, no Apify CLI, no Apify token — publishing and GitHub remain owner-gated (see WEEKLY_REPORT.md blockers).
- Pattern for all future actors: pure `transform.js` (testable without Apify SDK) + thin `main.js`; golden fixtures are trimmed REAL API captures (~10 KB).

## 2026-09-15 — revenue sprint (niche scan, price realignment, 5 builds)
- **Critical bug found in staging, fixed portfolio-wide:** `sinceLastRun` cursors were saved to `Actor.openKeyValueStore()` (the run's DEFAULT store), which is brand new on every run -> incremental mode never worked on SEC, TED, Federal Register, FDA (and first SAM.gov build): a scheduled customer would have been re-delivered and re-charged the same records daily. Fix: shared/js/incremental.js — cursor in a NAMED store (`factpipe-<slug>-state`, persists in the runner's account), boundary date re-read and deduplicated by record ID. Rule: every incremental actor must pass a two-pass staging test (pass 2 returns 0 new records).
- Free-text PII: dropping contact columns is not enough — SAM.gov descriptions embed contracting officers' emails and phones. Redact emails/phones in free text (separators required so solicitation numbers, NAICS codes and amounts survive).
- Market reality (niche_demand_scan.py, 54 safe niches): official-data niches are tiny and crowded (top-10 combined users/30d: SEC 26, sanctions 9-12, clinical trials 8) with prolific AI-generated catalogs everywhere (ryanclinton, nexgendata). Our prices were 2-4x competitor medians (SEC $8 vs $2) -> realigned to median (owner-approved P1). Best signal combo for new builds: small total result set (<300 -> page 1 by default) + real run volume + high incumbent failure rate (Lighthouse: 158-258 results, 7.5k-11.6k runs/mo, 15-24% failing).
- Local proxy 127.0.0.1:7897 makes Store API calls ~24s vs ~1.8s direct: run zero-token Apify scripts with `env -u HTTP_PROXY -u HTTPS_PROXY`. uv python 3.12 lacks CA certs for ec.europa.eu; use node fetch for captures.
- Build notes: SAM.gov publishes the full Contract Opportunities dataset as a keyless daily CSV (244 MB, Windows-1252, sorted by PostedDate desc) -> streaming parse with early stop reads ~10 MB for a 3-day window (13 s, $0.001/run); no SAM.gov account or login.gov needed. Lighthouse 12 runs fine in apify/actor-node-puppeteer-chrome:22 with `lighthouse(url, flags, config, page)`; ~$0.003 compute per audit at 2 GB. VIES returns MS_MAX_CONCURRENT_REQ inside HTTP 200 bodies — treat as transient, never as invalid, never charge. DNS null MX (RFC 7505) comes back as {priority:0, exchange:''}.
- 2026-09-15 live-product audit triggered by the SAM.gov two-pass test found 4 bugs in already-published actors, all fixed + regression-tested before any external user hit them: (1) incremental cursor in default store (SEC/TED/FedReg/FDA); (2) SEC date filters silently ignored without `dateRange=custom`+`enddt` (users got 2004-2018 results for "since Sept 1"); (3) SEC paginated `from += 10` over 100-hit pages -> runs over 100 results re-delivered and charged ~90% duplicates; (4) FDA/FedReg/TED/SEC stopped paginating when a page had one malformed record (parsed count < page size) -> FDA delivered 99 of 133. Also openFDA unsorted skip-paging is non-deterministic: always `sort=report_date:desc`. Rule: verify page size and date-filter semantics against the live API with a count check (delivered == API total) in staging, not just "non-empty results".
- Incremental design that survives unsorted sources and maxResults caps: a truncated run keeps its query start date and stores all delivered IDs (cap 20k); only a complete run advances the date watermark (boundary-date IDs kept). Free-plan note: account-wide 16 GB concurrent memory -> at most 4 builds at once.
- 2026-09-15 launch: price changes on a live Actor go through Console → Publishing → Monetization → Change (4-step wizard: pricing, primary event, reasoning, review). With no paying users the change applies immediately and the monthly change limit does not apply. The Monetization section header toggles open/closed: click the banner once (a ref click on the inner heading can toggle it twice). New-Actor wizard shows Apify's own cost estimate ("average usage cost per 1,000 results"): Lighthouse $2.13, VIES $0.36, email checker $0.11, ECB $0.04, SAM.gov $0.02, which matches staging measurements. Network flips: sometimes direct connections to api.apify.com time out and the proxy is fast; test both with one curl before long scripts.
- 2026-09-15 gap validation (scripts/gap_validation.py): Store `totalUsers30Days`/run stats include Apify's daily auto-test (1 user, ~30 runs per public Actor), so a niche of 40 Actors at "1 user, 29 runs" has zero customers. Always subtract it (keep 1 user when runs > 40). Match relevance on title/name only; descriptions of lead-gen/OSINT tools mention every keyword. Result: CPSC recalls 0 real users across 41 Actors, UK VAT 2, EU Safety Gate 2, Grants.gov 7, SEC Form 4 10, global sanctions 12 across 71. Only DNS lookup (78), broken links (45, 3.6k runs) and France Sirene (44) show real demand. "High usage + low rating + stale" barely exists: almost no reviews anywhere, failure rates ≤1%, most leaders rebuilt within 60 days.
