# Learnings (append-only)

## 2026-09-11 — bootstrap session
- Apify Store API (`/v2/store`) is public, no token needed, and returns 30-day run stats incl. FAILED counts, review ratings and full PPE pricing of incumbents — the whole opportunity scan is zero-token. `opportunity_scan.py` weights: log10(demand) × weakness × legal ÷ sqrt(build hours).
- Scan results 2026-09-11: uk-company-lookup demand dwarfs everything safe (21,687 incumbent runs/30d, unrated incumbents); TED incumbents fail 13.7% of runs (reliability is the wedge); SEC incumbents avg 4.0 rating with PPE at ~$0.01/filing (price+quality wedge). Google Trends & Product Hunt have big demand but fail our legal-safety filter — do not revisit.
- SEC full-text search endpoint `efts.sec.gov/LATEST/search-index` works keyless but REQUIRES a User-Agent header identifying the caller; page size fixed at 10; paginate with `from`.
- TED API v3 `POST /v3/notices/search` works keyless; multilingual fields come as `{lang: [values]}` maps (prefer `eng`); CPV codes arrive duplicated — dedupe; pagination via `page` or `iterationNextToken`.
- Companies House API has NO keyless access; decision: customers supply their own free key via secret input (removes our rate-limit exposure, zero owner ops). Officer/PSC data excluded from v1 as PII — owner legal call requested.
- Node 22.16 `node --test <dir>` fails; must glob `tests/*.test.mjs`.
- Local machine has no gh CLI, no Apify CLI, no Apify token — publishing and GitHub remain owner-gated (see WEEKLY_REPORT.md blockers).
- Pattern for all future actors: pure `transform.js` (testable without Apify SDK) + thin `main.js`; golden fixtures are trimmed REAL API captures (~10 KB).

- Actor creation via `POST /v2/acts` with `sourceType: GIT_REPO` + `gitRepoUrl ...#main:actors/<slug>` builds straight from the public monorepo — no per-actor deploy keys needed. All 3 builds succeeded first try.
- Staging runs: SEC + TED SUCCEEDED with real data; UK failed by design with the correct "bring your own key" error. Staging schedules `staging-sec-edgar` / `staging-eu-ted` run 2x/day (06:00/18:00 UTC) exercising `sinceLastRun`.
- SEC display names can carry ticker suffixes, e.g. "Piedmont Lithium Inc. (PLL, PLLTL)" — harmless, but a future polish is stripping ticker parens in cleanName().
- Chrome automation: `type` into GitHub inputs drops characters; use `form_input` with refs for anything that must be exact.
- 2026-09-11: CH developer key created (app `data-portfolio-staging`, key at `~/.companies_house_key`, chmod 600, staging-only). Live staging run caught a real billing bug: CH fuzzy search matched a nonsense query to an unrelated company and we'd have charged it. Fix: name match requires exact title or full token-subset (legal suffixes stripped); vague queries return found=false uncharged. Lesson: staging with adversarial inputs (including a guaranteed-miss query) is now mandatory for every lookup-type actor.
- CH developer hub gotchas: description field rejects digits/parentheses/periods; REST key type reveals extra fields; account sign-in needs an emailed OTP each new browser session (owner must relay the code — Claude cannot read the inbox).
- Apify publish gating discovered: PPE monetization config is per-actor in Console AND requires the account to have a PUBLIC PROFILE first (Settings). Username choice is permanent-ish (Store URLs) — owner decision D6 is therefore publish-blocking, not optional.
- 2026-09-11 (launch prep): Apify account renamed to `factpipe`, public profile live (apify.com/factpipe). PPE configured via Console wizard on all 3 actors (filing-result $0.008 / tender-result $0.01 / company-found $0.004); removed the default actor-start and dataset-item events so "empty runs never charged" stays literally true. Sensitive console saves silently fail on a stale session — re-auth first, then save. Publish = `isPublic: true` via PUT /v2/acts/{id}; `scripts/publish_actors.py` guards on 48h window + PPE present. One-off cloud routine `launch-first-actors` fires 2026-09-12T17:30Z.
- 2026-09-11 LAUNCH: all 3 actors public on Store (apify.com/factpipe/...), owner clicked T&C+Publish (legal agreement stays with owner). Publish gates discovered in order: public profile -> billing -> `.actor/output_schema.json` (new hard requirement; platform validator REJECTS the documented `resourceType` field — spec is ahead of implementation) -> T&C dialog (opens in a separate window Claude cannot drive; owner must click).
- Store auto-test rule: public actors run daily with DEFAULT input; 3 consecutive failures -> "under maintenance" flag. Every future actor must have a prefill input that succeeds non-empty in <5 min with zero credentials. This forced the UK actor keyless-by-default pivot (owner key as secret env var fallback) — which is also better conversion.
- `isPublic` cannot be set via API token (403) — Store publishing is console-only.
- 2026-09-11 batch 2 (same day as launch): 4 actors built+staged+priced in one session (federal-register $0.005, fda-recalls $0.005, ofac-screening $0.01, us-weather $0.002). Rule: every schema default must round-trip through a live staging run.
- Legal guardrail applied: Open-Meteo free tier forbids commercial use -> weather actor uses NWS api.weather.gov (US public domain). USPTO deferred (needs registration key + heavier build).
- Assembly-line metadata generation (actor.json/output_schema/Dockerfile/package.json from one script) works well; keep it for future batches.
- Apify Store enforces a hard limit of 5 Actor publications per 24h per account. Plan launch batches accordingly (we hit it on day one: 3 + 2). Remaining actors stay fully configured; only the owner's Publish+T&C click is pending after the window resets.
